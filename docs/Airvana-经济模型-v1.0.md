# Airvana 经济模型

> 版本：v1.0  
> 基线日期：2026-08-18  
> 决策状态：第一版产品基线  
> 适用范围：玩家、创作者、品牌 Campaign、订阅、平台权益与结算  
> 实施状态：本地全栈 V1 已实现；生产外部依赖见第 12 节

## 1. 一句话定义

Airvana 只保留两种用户可见的核心资产：

- **AIP：行为积分**，记录用户和创作者对平台产生的有效行为，用于创作消耗、站内权益和资格解锁。
- **AIT：活动权益与收益凭证**，记录经 Campaign Contract 约定并通过验证的活动贡献、权益或收益资格。

订阅不是第三种积分；现金或 USDT 也不是第三种积分。订阅提供功能与额度，现金或 USDT 只作为独立结算记录存在。

## 2. V1 不可变的经济边界

1. AIP 与 AIT 分账记录，不自动互换，不设置全局固定兑换率。
2. AIP 不可提现、不可转让、不可交易，不承诺现金或数字资产价值。
3. AIT 在 V1 中是中心化、不可自由转让、不可交易的权益与收益凭证，不是公开流通 Token。
4. 用户订阅直接获得功能和额度；V1 默认不赠送 AIP，也不产生 AIT。
5. 创作消耗顺序固定为：**订阅额度优先 → AIP 补充支付**，绝不消耗 AIT。
6. 普通试玩只奖励 AIP；Campaign 核心结果在 Contract、归因、资格和风控全部满足后才可能产生 AIT。
7. AIT 与现金或 USDT 的结算没有平台统一固定比率，币种、金额、结算主体和条件必须由获批的 Campaign Contract 决定。
8. 曝光、点击、点赞、收藏、普通分享和游戏开始默认不直接产生 AIT。
9. Campaign 的奖励、CTA、地区、归因、预算和结算属于锁定字段，普通用户、创作者或 Agent 不得自行修改。
10. 涉及数字资产、KYC、入金、交易或其他受监管行为时，必须经过地区、年龄、合同、合规和人工审批；默认关闭，失败时不发奖励。

## 3. AIP：行为积分

### 3.1 AIP 是什么

AIP 是 Airvana 的中心化平台行为积分，用于确认真实、有效、可验证的平台参与行为。AIP 是使用权和成长记录，不是货币、证券、储值余额或收益凭证。

### 3.2 AIP 的来源

以下为 V1 平台默认规则。所有事件都必须由服务端记账、幂等、防刷，并通过相应资格校验。

| 行为 | V1 默认 AIP | 频率与条件 | 说明 |
| --- | ---: | --- | --- |
| 完成注册、账号验证及首次有效试玩 | 100 | 每个真实用户一次 | 不因只填写注册表单立即发放 |
| 每日登录 | 5 | 每自然日一次 | 异常设备或批量账号不发放 |
| 连续登录 | 递增，7 日周期最高 30 | 每日一次 | 中断后重新计算周期 |
| 完整试玩一款游戏 | 5 | 同一用户、同一游戏、24 小时一次 | 必须完成规范运行事件链 |
| 完成每日推荐试玩 | 20 | 每自然日一次 | 与普通试玩是否叠加由活动配置明确 |
| 有效邀请好友 | 100 | 每位合格受邀用户一次 | 受邀用户完成验证和首次有效试玩后发放 |
| 创作者作品审核通过并首次发布 | 50 | 每个新作品一次 | 重复提交、恢复旧版本不重复发放 |
| 已发布作品完成有效版本优化 | 20 | 每个获批版本一次 | 必须有真实变更和审核记录 |
| 持续运营任务 | 10–30 | 按任务规则 | 以有效运营行为和证据为准 |
| 点赞、收藏、普通分享 | 0 | 默认不奖励 | 只记录互动与归因，降低刷分风险 |

以上数值是 V1 默认运营参数，可由平台版本化调整；调整只影响生效后的事件，不追溯修改已入账记录。Campaign 不得绕过 Contract 临时放大 AIP 奖励。

### 3.3 AIP 的消耗

AIP 只消耗在明确的站内功能和权益上：

- 订阅额度用完后的轻度创作、深度创作、重新生成、图片和音效生成。
- Remix、版本扩展、额外生成尝试。
- 作品 Boost、主题、身份展示、资料装饰等非金融权益。
- 进入特定 Campaign 或兑换 Campaign 非金融权益，但必须由 Contract 明确允许。

V1 初始测算参数如下，正式上线前必须按真实模型和媒体成本复核：

| 消耗项 | V1 测算值 | 状态 |
| --- | ---: | --- |
| 轻度创作 | 50 AIP | 待成本校准 |
| 深度创作 | 300 AIP | 待成本校准 |
| Remix | 30 AIP | 待成本校准 |
| 局部重新生成 | 20–100 AIP | 根据任务复杂度 |
| 单次图片生成 | 20 AIP | 待供应商成本校准 |
| 单次音效生成 | 30 AIP | 待供应商成本校准 |
| 作品 Boost 24 小时 | 20 AIP | 当前原型已有服务端能力 |

扣减规则：订阅额度优先，额度不足时才扣 AIP；AIP 按最早过期批次优先扣减；余额不足时不允许形成负余额。

### 3.4 AIP 的期限

- 标准 AIP：自入账之日起 12 个月有效。
- Campaign 或推广 AIP：30–90 天，由活动规则明确具体到期日。
- 退款、撤销或风控恢复：沿用原批次到期日，不重新延长有效期。
- 消耗顺序：最早到期批次优先。
- 提醒：到期前 30 天、7 天和 1 天提醒用户。
- 已过期 AIP 保留历史记录，但不可再使用。

### 3.5 AIP 账本状态

`pending → posted → frozen / spent / expired / reversed`

- `pending`：等待事件或风控验证。
- `posted`：已可使用。
- `frozen`：争议、异常或风控调查中，暂不可使用。
- `spent`：已用于站内功能或权益。
- `expired`：超过有效期。
- `reversed`：原事件无效、退款或违规后撤销。

## 4. AIT：活动权益与收益凭证

### 4.1 AIT 是什么

AIT 是 Airvana 对 Campaign 中已约定贡献、权益或收益资格的中心化记账凭证。它用于表达“该用户或创作者在某个 Campaign 中具有什么经验证的权益”，而不是表达平台通用现金价值。

V1 用户界面可简称“AIT”，对外完整名称统一使用“活动权益与收益凭证”。除非未来完成独立的产品、法律、税务、支付和链上方案审批，不使用“可交易 Token”“投资资产”或“固定兑付资产”等表述。

### 4.2 AIT 的来源

AIT 只能由获批的 Campaign Contract 产生，并绑定 `campaign_id`、Contract 版本、来源事件、归因证据和审核记录。

| 来源类型 | 获得主体 | 触发条件 |
| --- | --- | --- |
| `player_campaign` | 玩家 | 完成 Contract 指定核心操作，归因、资格、反作弊和人工/合作方验证全部通过 |
| `creator_delivery` | 创作者 | Campaign 交付物经品牌和平台审核通过 |
| `creator_operation` | 创作者 | 完成获批的持续运营任务并提交有效证据 |
| `creator_performance` | 创作者 | 达到 Contract 明确的非违规表现条件，并通过归因与无效流量核验 |
| `campaign_allocation` | 玩家或创作者 | Campaign 预算内、经过授权的专项权益分配 |

以下行为默认不产生 AIT：订阅、充值 AIP、普通试玩、点赞、收藏、普通分享、仅点击 CTA、仅启动注册/KYC 流程，以及没有完成验证的营销事件。

### 4.3 AIT 的使用与减少

AIT 不用于创作、模型调用、图片生成、Boost 或购买订阅。AIT 只会因以下情况减少：

1. 领取该 Campaign 明确提供的非金融权益。
2. 进入经批准的结算流程后锁定并完成结算。
3. 归因无效、重复、作弊、退款、违约或审核纠错导致撤销。

任何现金或 USDT 结算都应生成独立的结算记录，包括法币金额、支付币种、汇率来源与时间、付款主体、收款主体、费用、状态和凭证。AIT 账本不得直接伪装成现金钱包。

### 4.4 AIT 的期限

- `estimated` / `pending`：按 Campaign 的验证窗口和申领窗口到期；具体日期必须写入 Contract。
- `available`：已验证且已落实预算的 AIT，V1 不设置任意自然到期；只可因结算、领取权益、违规撤销或账户依法关闭而变化。
- `frozen`：调查期间不计算到期，解除后恢复原状态或撤销。
- `settled`：永久保留结算记录，不再作为可用余额。
- `reversed` / `expired`：永久保留审计记录，不可再次使用。

### 4.5 AIT 状态机

`estimated → pending → available → frozen / settlement_pending → settled`

异常分支：`estimated / pending / available / frozen → reversed`；超过 Contract 验证或申领窗口的未确认权益进入 `expired`。

## 5. 订阅机制

### 5.1 订阅是什么

订阅是周期性的功能权限、创作额度和服务等级，不是积分购买，也不是收益产品。

V1 订阅购买后：

- AIP 增加 0。
- AIT 增加 0。
- 直接增加对应周期的创作额度、容量、工具、分析和服务优先级。
- 未用完的周期额度默认不结转，除非套餐规则明确允许。

如果未来开展“订阅赠送 AIP”活动，必须使用独立的 `subscription_bonus` 批次、明确有效期，并标记 `campaign_eligible=false`，不得用于制造 AIT 或提高 Campaign 收益。

### 5.2 V1 套餐结构

| 套餐 | 主要对象 | 核心权益 |
| --- | --- | --- |
| Free | 新用户、轻量玩家与创作者 | 基础试玩、少量轻度创作、一次深度创作体验、基础模板、基础数据 |
| Creator Pro | 持续创作和运营的 KOL/创作者 | 更多轻度与深度创作额度、更多在运作品、素材空间、版本历史、高级分析、优先生成、域名/导出/协作能力 |
| Brand / Campaign | 品牌与 Campaign 团队 | Brief 与 Contract、成员权限、素材与审批、归因、预算和权益池、结算审计、报表、API 或白标能力 |

具体价格、月度额度和超额费用不在本模型中虚构，必须依据真实模型成本、媒体成本、存储、审核和客户服务成本单独定价并审批。

### 5.3 创作与模型选择

- 用户侧保留“轻度创作”和“深度创作”两种主要入口。
- 可提供“快速 / 均衡 / 高质量”偏好，但不直接展示或承诺具体供应商模型。
- 后端根据 Campaign Contract、内容风险、能力、质量、延迟、地区、预算和服务健康状态进行模型路由。
- 模型切换不形成第三种积分，所有超额创作仍只使用订阅额度或 AIP。

## 6. 不同游戏的积分是否一致

平台基础 AIP 规则保持一致，游戏内部成绩和 Campaign 权益可以不同。

| 事件 | 平台默认奖励 |
| --- | ---: |
| `playable_start` | 0 AIP |
| `step_complete` | 0 AIP |
| 首次有效 `playable_complete` | 5 AIP |
| 同一游戏 24 小时内重复完成 | 0 AIP |
| 过快完成、事件顺序错误、作弊或无效流量 | 0 AIP，并进入风险判断 |

统一基础奖励的原因：避免用户只挑高积分游戏、避免创作者通过调高难度制造积分、保持推荐系统和反作弊可解释。

不同游戏允许存在：

- 不同的游戏内分数、星级、道具和排行榜。
- 不同的 Campaign 核心结果和 AIT 数量，但必须由获批 Contract 锁定。
- 不同的完成时长、难度和玩法，不因此自动改变基础 AIP。

## 7. 营销核心操作奖励什么

V1 采用“软行为给 AIP，验证后的商业结果给 AIT”的原则。

| 用户动作 | 默认结果 | 原因 |
| --- | --- | --- |
| 曝光、浏览 | 只记事件，不奖励 | 无法证明有效贡献 |
| CTA 点击 | 只做归因，不奖励 | 点击不是最终结果 |
| 游戏开始、步骤完成 | 只记进度，不奖励 | 防止中途退出刷分 |
| 完整有效试玩 | 5 AIP | 平台参与行为 |
| 点赞、收藏、普通分享 | 0 AIP / 0 AIT | 默认不为低成本行为付费 |
| 有效邀请并完成首玩 | 100 AIP | 平台增长行为，需去重和反作弊 |
| Campaign 核心操作已发生但待验证 | `pending AIT` | 尚未满足结算条件 |
| 核心操作通过归因、资格、风控和预算验证 | `available AIT` | 已形成 Contract 约定权益 |
| 创作者交付审核通过 | `pending AIT` 或独立结算待确认 | 取决于 Contract 的创作者条款 |

下载、注册、KYC、入金、充值、交易等不得成为全平台默认奖励事件。若特定 Campaign 确需使用，必须逐一明确地区、年龄、合规主体、资格、归因、预算、上限、申诉、失败处理和人工审批，且不得宣称保证收益。

## 8. 玩家、创作者与品牌的价值流

### 8.1 玩家

`登录/试玩/邀请 → 获得 AIP → 解锁站内创作或权益`

`进入获批 Campaign → 完成核心操作 → 归因与审核 → 获得 pending/available AIT → 领取 Contract 权益或进入独立结算`

### 8.2 创作者

`订阅额度 → 创作与运营 Agentic Playable → 超额部分消耗 AIP`

`获批交付/运营/表现 → 获得 AIT 或形成结算资格 → 审核与对账 → 独立结算`

创作者不会因为购买订阅直接获得收益，也不会通过消耗 AIT 进行创作。

### 8.3 品牌

`Campaign Brief → Campaign Contract → 预算与权益池 → KOL/Playable 投放 → 归因与验证 → AIT 分配/创作者结算 → 对账与复盘`

品牌预算不是用户可交易的 AIT 资金池；预算、权益、付款和 AIT 分配必须分别记账。

## 9. 统一账本字段

AIP 与 AIT 必须使用可审计的服务端账本，至少包含：

- `ledger_event_id`
- `user_id`
- `asset_type`：`AIP` 或 `AIT`
- `amount` 与 `direction`
- `source_type` / `event_type`
- `subject_type` / `subject_id`
- `campaign_id` 与 `contract_version`（AIT 必填）
- `status`
- `earned_at`、`available_at`、`expires_at`
- `frozen_at`、`spent_at`、`reversed_at`
- `idempotency_key`
- `risk_decision` 与 `reason_code`
- `metadata` 与审计操作者

账本要求：禁止客户端直接改余额；每个奖励事件必须幂等；余额必须从有效账本事件汇总；冻结、撤销和过期不得删除原记录。

## 10. Campaign Contract 必须锁定的经济字段

每个 Campaign 至少锁定以下字段后，AIT 才能进入生产流程：

- 主要目标和唯一主要成功事件。
- 参与地区、年龄、身份和其他资格。
- 玩家与创作者的 AIT 规则、总预算、单用户上限和活动上限。
- 归因窗口、去重规则、无效流量规则和证据来源。
- 验证方、审核方、申诉窗口和失败处理。
- 权益类型；如存在现金或 USDT 结算，明确币种、金额或计算方式、付款主体、收款主体和结算条件。
- CTA 目的地、合规文案、暂停条件和 Kill Switch。

Agent、KOL 和普通运营人员只能修改 Contract 允许的创意字段，不能修改上述经济与合规字段。

## 11. 风控与治理

- 同设备、同身份、同支付或同归因主体的重复账号必须合并判断。
- 过快完成、事件顺序错误、批量设备、异常邀请和异常网络进入风险队列。
- 奖励先 `pending`，通过校验后再 `posted` 或 `available`。
- 高价值 AIT、跨地区、受监管行为和结算必须人工复核。
- 用户可以查看冻结、撤销、过期原因，并在规定窗口内申诉。
- 平台管理员只能通过有原因码、操作者和审计记录的调整事件修正余额。

## 12. 实施状态与生产外部依赖

本地全栈 V1 已完成统一账本、批次期限、订阅额度、创作计费、玩家/KOL 权限、Contract 经济规则、AIT 权益、独立付款记录、冻结、撤销与申诉。旧 AIT 通用提现 API 固定返回 `410`，仅保留旧数据库表用于已有数据迁移，不再产生新的提现记录。

以下不是本地产品逻辑缺口，而是生产上线前必须接入并审批的外部依赖：

1. 合规 KYC 服务商及只保存状态/凭证引用的集成。
2. 品牌或合作方的权威成功事件与归因证据来源。
3. 真实付款服务商、托管/钱包策略、付款回执与财务对账。
4. 定时执行过期、风控复核、告警和运营审计的生产任务基础设施。
5. 订阅价格、退款、税费、目标地区及 AIT 结算条款的商业和法律批准。

完整代码、API 与状态机说明见 [Airvana-经济模型-v1.0-实现说明.md](Airvana-经济模型-v1.0-实现说明.md)。

- 为轻度/深度创作建立可配置成本，而不是暴露供应商模型。

### P2：Campaign AIT 闭环（已完成本地状态机）

- 建立 Contract 驱动的奖励规则、预算、归因、验证、冻结、申诉和结算状态机。
- 玩家与创作者分别使用明确的 AIT 来源类型。
- 所有高风险或受监管行为默认关闭，只有审批通过的 Contract 可以启用。

## 14. V1 验收标准

- 任意页面对 AIP、AIT 和订阅的定义一致。
- 订阅成功不会直接增加 AIP 或 AIT。
- 创作只消耗订阅额度或 AIP，不能消耗 AIT。
- 所有普通游戏完成基础奖励一致为 5 AIP，并有每日去重和运行证明。
- AIT 只能由获批 Campaign Contract 产生，并能追溯归因和审核证据。
- AIT、现金和 USDT 分账展示，不存在平台全局固定兑换率。
- 过期、冻结、撤销、结算和申诉均保留完整审计记录。
- 未通过地区、资格、归因、风控或预算校验的事件不发奖励。

## 15. 版本变更规则

- 本文是 Airvana 第一个经济模型版本，也是后续实现和产品文案的默认基线。
- 修改 AIP/AIT 定义、可转让性、可交易性、固定兑换、结算资产或受监管奖励行为，必须升级主版本并经过产品、财务、风控与法律审核。
- 修改具体 AIP 数值、订阅额度或运营上限，可在不改变核心边界的情况下升级次版本，但必须记录生效时间和用户影响。
- 单个 Campaign 的经济规则不得修改平台定义，只能在获批 Contract 的锁定字段内配置。
