# Airvana 产品契约（权威口径）

这里是**产品承诺的唯一真相**：经济规则的数值、边界声明的原文、风控口径的措辞。

## 为什么要有这一层

在此之前，一部分产品口径只存在于 `public/index.html` 的文案里——比如地区风控
那段「IP 仅作为风险信号，最终权限仍由账号、KYC、Campaign Contract 与服务端策略
确认」。Web 原型是活的代码，随手一改这些承诺就没有权威出处了，各端也会各自漂移。

本目录把它们提取成结构化文件，后端（`src/`）与移动端（`apps/airvana_mobile/`）
各自有测试断言自己符合这份契约。任何一端改了数值或删了边界声明，测试会失败。

## 契约文件

| 文件 | 内容 | 谁在校验 |
| --- | --- | --- |
| `economy.json` | 签到阶梯、AIP 奖励规则、三类资产的边界声明 | 后端 `test/product-contract.test.mjs`、移动端 `test/product_contract_test.dart` |
| `risk-modals.json` | 弱网 / 离线 / 地区风控三个弹窗的完整文案与按钮 | 移动端 `test/product_contract_test.dart` |

## 改动规则

1. **先改契约，再改实现。** 契约文件是评审对象；实现只是跟随。
2. 数值与文案**逐字**生效。改一个字就是改一次产品承诺，应当走产品评审。
3. 不要把「当前实现恰好是什么」写进来。这里写的是**应该是什么**。
4. 契约变更必须同时更新两端实现，否则两端测试会各自失败——这是有意的。

## 不属于这里的内容

- 界面布局、间距、动效：这些是设计层，归 Web 原型与设计系统。
- 服务端内部实现（表结构、幂等键）：归 `src/` 与后端文档。
- 演示用的占位数据：归各端自己，且必须标明是演示值。
