# Airvana 游戏补充与跨游戏 Power 可执行需求文档

> 文档版本：v1.0  
> 文档日期：2026-08-24  
> 文档状态：`REQUIREMENTS_READY`  
> 实施状态：`PLANNED`，本文完成不代表功能已经开发  
> 当前边界：移动端前端本地闭环；服务端、真实排行榜、真实多人协作、真实奖励、真实外部分发暂不开发  
> 产品定位：让每一个 KOL 创作并运营属于自己的 Agentic Playable。KOL 是创作者、所有者和运营者；Agentic Playable 是营销智能体。

---

## 0. 文档用途

本文把已确认的游戏补充建议转化为一份可以直接进入设计、开发、跟踪和验收的执行基线，解决以下问题：

1. 明确应该新增哪些核心玩法，而不是继续增加重复换皮游戏。
2. 把每日挑战、收藏、分享和 Remix 等平台能力与具体游戏模板分开建设。
3. 给每个需求分配稳定编号、优先级、状态、依赖、交付物和验收标准。
4. 建立统一评测方法，只有达到通过门槛的游戏才可以标记为完成。
5. 保证前端本地演示不会制造真实联网、真实奖励、真实审核或真实商业发布的假象。

本文是产品级模板能力建设需求，不是某一个品牌 Campaign 的生产 Contract。具体品牌 Campaign 仍必须遵循：

`Campaign Brief → Campaign Contract → PlayableConfig → 素材/权限校验 → 构建 → 审核 → 发布/回滚`

## 1. 当前基线与问题定义

### 1.1 当前基线

当前项目已有 38 款本地游戏：

- 32 款 Complete Games；
- 6 款 Deep Games；
- 已覆盖跑酷、漂移、射击、防守、答题、排序、节奏、换装、迷宫、经营、卡牌战术、叙事 RPG、证据推理、六角策略、三消装修等玩法；
- 现有游戏继续保留，不因本需求重写或下架。

### 1.2 当前主要缺口

当前缺口不是数量不足，而是以下能力覆盖不足：

| 缺口 | 当前表现 | 本期处理方式 |
| --- | --- | --- |
| 产品展示型互动 | 现有玩法偏战斗、解谜和操作，缺少清洁、修复、制作等产品体验 | 新增 ASMR、模拟制作模板 |
| 品牌认知 | 缺少围绕品牌对象和产品卖点的主动寻找玩法 | 新增寻物/找不同模板 |
| 导购与推荐 | 现有商店玩法是订单履约，不是需求分析与产品匹配 | 新增产品匹配/配置器模板 |
| 物理反馈 | 部分游戏具有时机操作，但缺少可复用的物理挑战模板 | 新增物理挑战模板 |
| KOL 传播 | 点赞、评论和分享存在，但缺少结构化挑战和结果卡 | 新增异步挑战、分享结果卡 Power |
| 留存 | 缺少统一每日任务、连续记录和跨游戏收藏 | 新增每日挑战、收藏成就 Power |
| 共创 | Remix 入口存在，但缺少可验证的字段权限和派生版本闭环 | 新增 Remix 关卡工坊 Power |

### 1.3 本期目标

本期交付以下两组能力：

#### A. 五个新增核心玩法模板

1. ASMR 清洁与修复；
2. 寻物与找不同；
3. 产品匹配与配置器；
4. 物理挑战；
5. 模拟制作。

#### B. 五个跨游戏 Power

1. KOL 异步挑战；
2. 每日挑战与连续记录；
3. 收藏册与成就；
4. Remix 关卡工坊；
5. 个性化分享结果卡。

### 1.4 成功定义

本期成功不是“页面已经出现”，而是同时满足：

- 五个玩法模板均具有开始、进行、成功、失败、重试、暂停、恢复、退出闭环；
- 五个 Power 均能至少接入两个现有游戏和一个新增游戏；
- APP 刷新或重启后，本地业务状态仍然一致；
- 游戏、首页卡片、个人主页、体验记录使用同一 `playable_id`；
- 所有关键动作产生本地审计事件；
- 360×800、390×844、430×932 三种移动端视口通过；
- 评测总分不低于 85/100，且不存在阻断级问题；
- 所有本地模拟状态均明确标记，不展示真实联网或真实奖励成功。

## 2. 范围与非范围

### 2.1 本期范围

- 新增五个可复用前端玩法模板；
- 建立统一的游戏模板注册、状态机、运行记录和事件接口；
- 建立五个跨游戏 Power；
- 接入创作者快速模式的模板推荐、Power 推荐、Review 和预览流程；
- 本地版本化持久化、恢复、重置、导出和审计；
- 移动端浏览器、iOS WebView、Android WebView 的前端行为验证；
- 自动化测试、移动视口验证和视觉回归基线；
- 本地 DEMO 素材清单、授权状态和降级策略。

### 2.2 本期非范围

- 真实实时 PVP、MMO、MOBA、RTS、3D FPS/TPS；
- 真实用户排行榜、跨设备同步和服务器反作弊；
- 真实社区共同进度；
- 真实优惠券、抽奖、数字货币、现金或链上奖励；
- 真实 KYC、注册、购买或结算成功；
- 真实 OAuth、外部社交媒体自动发布或归因；
- 未经批准的品牌 Logo、产品图、角色 IP 或商业素材；
- 服务端 API、数据库和消息队列实现。

### 2.3 真实性边界

服务端未接入时，界面只能使用以下口径：

- `本机挑战记录 · 本地演示`
- `已保存到本机`
- `已发布到本机 Airvana 首页 · 本地演示`
- `本地收藏进度`
- `本机模拟审核`

禁止显示：

- `全网发布成功`
- `真实排名`
- `奖励已到账`
- `注册/KYC/购买成功`
- `品牌审核已通过`
- `已完成真实归因或结算`

## 3. 用户与核心场景

### 3.1 玩家

玩家需要：

- 在 3 秒内理解玩法；
- 单手完成主要操作；
- 在 30–180 秒内获得一轮明确结果；
- 可以失败、重试、暂停、退出和恢复；
- 看到自己的本地挑战、收藏和成就；
- 分享结果但不被强迫授权或连接钱包。

### 3.2 KOL/创作者

KOL 需要：

- 从自然语言创意中获得模板和 Power 推荐；
- 选择或移除 Power；
- 在允许范围内调整主题、难度、文案和关卡参数；
- 试玩、审核、发布本地版本；
- 创建 Remix 派生版本并保留来源关系；
- 查看本地体验和传播演示数据。

### 3.3 品牌运营/审核人员

本期只提供前端演示能力，要求可以查看：

- 模板类型与玩法规则；
- 素材来源和授权状态；
- 可编辑字段、锁定字段和 Agent 可优化字段；
- 成功、失败、CTA、分享与奖励边界；
- 本地审核结果、版本、暂停和回滚入口。

## 4. 统一产品与技术约束

### 4.1 稳定对象 ID

所有模板和 Power 必须使用稳定 ID，不用展示名称作为关联键：

| 对象 | 字段 |
| --- | --- |
| 游戏模板 | `template_id` |
| Agentic Playable | `playable_id` |
| 版本 | `version_id` |
| 本地构建 | `build_id` |
| 运行会话 | `session_id` |
| 体验记录 | `run_id` |
| 挑战 | `challenge_id` |
| Remix 来源 | `parent_playable_id`、`parent_version_id` |
| 收藏项 | `collectible_id` |
| 审计事件 | `audit_event_id` |

### 4.2 统一状态机

每个新增游戏必须至少实现：

```text
idle
→ intro
→ playing
→ paused
→ success | failure | cancelled
→ retry | exit
```

持久化恢复增加：

```text
playing
→ backgrounded
→ resumable
→ playing
```

弱网或未来 Repository 接口不可用时：

```text
network_required
→ offline_blocked
→ retry | local_fallback | exit
```

本期纯本地核心玩法不得因为网络不可用而失去基本可玩性。

### 4.3 Repository 预留

前端业务层只依赖 Repository 接口，不直接调用未来服务端：

- `GameTemplateRepository`
- `PlayableRepository`
- `RunRecordRepository`
- `ChallengeRepository`
- `CollectionRepository`
- `RemixRepository`
- `AuditRepository`

本期实现 `Local*Repository`；远程实现仅保留接口和未接入状态。

### 4.4 公共状态

每个模板和 Power 必须有：

- Loading；
- Empty；
- Error；
- Offline；
- Permission blocked；
- Paused；
- Recoverable；
- Unsupported device；
- Asset fallback。

### 4.5 Campaign 字段权限

默认可编辑字段：

- 主题色；
- 标题与非合规文案；
- 允许范围内的视觉主题；
- 难度；
- 关卡时长；
- 对象数量；
- 非商业音效；
- 站内可见性；
- Remix 开关。

默认锁定字段：

- 品牌声明；
- CTA 地址；
- 奖励与资格；
- 地区和年龄；
- 归因与结算；
- 数据政策；
- Campaign 审核状态；
- Kill Switch 责任人。

## 5. 新增核心玩法模板需求

## 5.1 GME-P0-001：ASMR 清洁与修复

### 目标

建立适合产品体验、品牌展示和解压留存的单手互动模板。

### 推荐场景

- 球鞋、包袋和服装焕新；
- 电子设备清洁与修复；
- 食品、饮品和护肤制作过程；
- 家居整理和旧物修复。

### 核心循环

`选择工具 → 清除表层污渍 → 处理细节 → 修复/装饰 → 前后对比 → 评分/分享`

### 必须功能

- 至少 3 个连续阶段；
- 每个工具有不同作用区域和反馈；
- 对象具备脏污、清洁、修复完成三类可验证状态；
- 支持触摸拖拽、点击备用操作和静音；
- 错误工具不会直接卡死，需给出提示或轻度扣分；
- 成功后展示前后对比；
- 支持暂停、恢复、重试和退出；
- 默认无随机真实奖励。

### 素材最小集

- 1 个核心对象的 3–5 个状态层；
- 3–5 个工具；
- 污渍、泡沫、水渍、修复和完成特效；
- 6–10 个短音效，全部支持静音；
- 1 张完成结果卡背景。

### 验收标准

- 新用户 3 秒内可以完成第一次有效清洁动作；
- 三阶段均可完成且每阶段反馈不同；
- 关闭音效后不影响关卡完成；
- 中途退出重进可恢复当前阶段；
- 无素材时进入安全降级，不出现空白或不可操作状态；
- 目标单局时长 60–150 秒。

---

## 5.2 GME-P0-002：寻物与找不同

### 目标

建立用于品牌认知、产品卖点识别和安全教育的观察型模板。

### 核心循环

`查看目标 → 浏览场景 → 点击目标 → 获得反馈 → 使用提示 → 完成清单`

### 必须功能

- 支持“寻物”和“找不同”两种配置；
- 每关 5–12 个目标；
- 错误点击有节制反馈，不造成不可恢复失败；
- 提示功能有冷却或次数限制；
- 支持缩放时不得破坏点击坐标；
- 目标列表、已找到状态和剩余时间可读；
- 支持无计时的无障碍模式；
- 品牌对象必须参与玩法，不只作为背景装饰。

### 素材最小集

- 至少 2 张高信息密度场景；
- 每张场景的目标遮罩和坐标清单；
- 寻物目标缩略图；
- 找不同的双图或差异层；
- 提示高亮、正确和错误反馈素材。

### 验收标准

- 所有目标命中区与视觉位置一致；
- 360px 宽度下可完成缩放、平移和点击；
- 目标随机顺序不产生不可达状态；
- 无计时模式能够完成全部内容；
- 完成、失败、提示、重试事件完整；
- 目标单局时长 45–120 秒。

---

## 5.3 GME-P0-003：产品匹配与配置器

### 目标

建立面向导购、需求分析、产品教育和结果分享的结构化推荐模板。

### 核心循环

`回答需求 → 调整偏好 → 组合配置 → 查看匹配解释 → 保存/分享结果 → 可选 CTA`

### 必须功能

- 3–6 个核心问题，每轮只显示一个关键问题；
- 支持跳过非关键问题并展示所用默认值；
- 推荐结果必须显示“为什么匹配”；
- 支持返回修改单个答案；
- 产品数据可以使用本地 DEMO 数据，但必须明确标记；
- 未接品牌数据时不显示真实库存、价格或购买成功；
- CTA 仅在 Contract 允许的状态出现；
- 推荐逻辑必须确定性可复测，不能只使用随机结果。

### 素材最小集

- 问题和选项图标；
- 3–8 个演示产品/方案卡；
- 结果解释组件；
- 对比表；
- 分享结果卡模板。

### 验收标准

- 相同输入在相同版本下得到相同结果；
- 跳过问题后明确展示默认值；
- 修改答案会重新计算结果且不产生重复记录；
- 无 CTA 或离线时仍可完成站内结果体验；
- 结果页不伪造价格、库存、购买或转化；
- 目标单局时长 45–90 秒。

---

## 5.4 GME-P0-004：物理挑战

### 目标

建立适合单手操作、快速传播和反复挑战的通用物理反馈模板。

### 核心循环

`拖拽/蓄力 → 瞄准 → 释放 → 碰撞/落点 → 评分 → 重试/分享`

### 必须功能

- 支持弹射、投掷、平衡中的至少两种配置；
- 轨迹预测可配置开关；
- 同一版本同一输入的结果允许小范围物理误差，但不得完全随机；
- 支持三次快速重试，不重复进入加载页；
- 失败原因明确，如距离不足、越界、碰撞失败；
- 可通过参数调整重力、阻尼、目标大小和容错；
- 页面滚动不得抢占游戏内拖拽手势。

### 素材最小集

- 主操作物体；
- 目标、障碍和落点素材；
- 轨迹、碰撞和得分特效；
- 至少 2 套场景主题；
- 结果卡视觉。

### 验收标准

- 触摸、鼠标和 WebView 手势行为一致；
- 操作区域内拖拽不触发页面滚动；
- 60fps 目标设备下无持续明显掉帧；
- 三种移动视口无遮挡；
- 成功、失败、重试和暂停恢复完整；
- 目标单局时长 20–60 秒。

---

## 5.5 GME-P0-005：模拟制作

### 目标

建立面向产品流程教育、品牌种草和组合创作的制作型模板。

### 核心循环

`选择材料 → 按顺序加工 → 组合 → 包装/装饰 → 结果评分 → 分享`

### 必须功能

- 支持 3–6 个制作步骤；
- 支持步骤顺序要求和自由创作两种模式；
- 配方/订单目标可见；
- 材料选择会影响最终结果；
- 错误步骤提供纠正，不产生无说明死局；
- 结果必须由实际选择生成，不使用无关随机图；
- 支持保存本地配方和再次制作；
- 商业品牌素材进入前必须检查授权状态。

### 素材最小集

- 6–12 个材料/部件；
- 3–5 个工具或加工动作；
- 制作台、包装和结果场景；
- 中间状态组合图层；
- 结果卡模板。

### 验收标准

- 每一步操作与可见结果一致；
- 顺序模式能够检测并解释错误步骤；
- 自由模式至少生成 6 种可区分结果；
- 本地配方刷新后仍可读取；
- 缺少素材时使用明确占位，不伪造品牌成品；
- 目标单局时长 60–180 秒。

## 6. 跨游戏 Power 需求

## 6.1 PWR-P0-001：KOL 异步挑战

### 目标

将可评分游戏转换为可分享、可重复挑战的 KOL 传播闭环。

### 流程

`完成游戏 → 生成挑战记录 → 生成挑战卡 → 本地接受挑战 → 比较成绩 → 再次挑战`

### 要求

- 支持分数、用时、完成度三种成绩口径；
- 挑战记录绑定 `playable_id`、`version_id` 和规则版本；
- 不同版本不可直接合并排名；
- 本期只记录本机挑战；
- 明确显示 `本机挑战记录 · 本地演示`；
- 为未来服务器校验、反作弊和真实排行榜保留 Repository 接口。

### 首批接入

- 物理挑战；
- 霓虹疾跑；
- 节拍熔炉。

### 验收

- 挑战卡可打开正确游戏和版本；
- 重复挑战不会覆盖原始成绩；
- 退出和重进后挑战记录仍存在；
- 不展示“全球、好友或全网排名”。

---

## 6.2 PWR-P0-002：每日挑战与连续记录

### 目标

为现有游戏建立可复用的本地留存机制。

### 要求

- 每天最多一个主任务，可附加两个可选任务；
- 使用本地自然日和时区记录；
- 防止简单重复刷新领取；
- 连续记录中断规则明确；
- 修改设备时间时记录异常审计事件并安全降级；

## 9. 美术、音频与“保真去 AI 味”标准

### 9.1 素材交付流程

`素材规划 → 视觉方向确认 → ImageGen/人工制作 DEMO 素材 → UI 组合 → 图集化 → 运行时接入 → 浏览器真机视口验证 → 授权复核`

### 9.2 每个模板的素材清单必须包含

- `asset_id`；
- 文件路径；
- 素材用途；
- 来源；
- 所有者；
- 授权状态；
- 适用语言和地区；
- 版本或 checksum；
- 失效日期；
- 降级素材；
- 人工审核状态。

### 9.3 视觉验收

- 核心可交互对象不能只使用无设计的矩形和圆形占位；
- 风格、透视、光向、边缘、材质和比例保持一致；
- 关键对象在手机宽度下可辨认；
- 文字不得被生成进位图作为正式 UI；
- 场景素材不能压过操作目标；
- 生成素材统一标记 `LOCAL_DEMO`，不得视为已获商业授权；
- 不得从应用市场截图直接切取商业素材作为发布资源。

### 9.4 音频验收

- 默认遵守系统静音；
- 一键静音；
- 离开页面停止播放；
- 音频加载失败不影响可玩性；
- ASMR 模板必须同时提供视觉/触觉反馈替代，不能只依赖声音。

## 11. 测试与评测体系

### 11.1 测试层级

1. **单元测试**：状态机、计分、推荐、日期、收藏和字段权限。
2. **组件测试**：按钮、弹窗、输入、暂停、错误和空状态。
3. **闭环测试**：开始、成功、失败、重试、暂停、恢复、退出和结果。
4. **跨页面一致性测试**：首页、个人主页、草稿、体验记录和收藏。
5. **移动端测试**：360×800、390×844、430×932。
6. **真机测试**：iPhone、Android 的键盘、安全区、返回、刷新和异常退出。
7. **视觉回归**：核心状态截图和差异阈值。
8. **审计测试**：关键动作事件字段完整、顺序正确、无重复成功。

### 11.2 每个游戏的强制用例

| 测试 ID | 场景 | 预期结果 |

- 锁定字段可被 Remix 绕过；
- 展示虚假的真实排名、奖励到账、审核通过或全网发布；
- 收集私钥、助记词、原始 KYC 文件或非必要敏感信息；
- 使用无授权商业素材作为正式发布素材；
- 严重横向溢出、关键按钮不可点击或真机无法操作；
- 关键事件缺失，无法区分开始、完成和退出。

- 代码已合入确认范围；

- 自动化测试通过；
- 三个移动端视口通过；

- 刷新、重启和数据恢复测试通过；
- 首页、个人主页、草稿和体验记录状态一致；
- 评测 ≥85；

## 14. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 继续把相似换皮当成新游戏 | 数量增加但能力未增加 | 以核心循环和模板能力去重 |
| 高保真素材拖慢开发 | 模板逻辑迟迟无法验证 | 先用明确 DEMO 素材验证闭环，再进行素材 Gate |
| Power 与游戏强耦合 | 每接入一个游戏都要重写 | 使用统一事件、计分、状态和 Repository 接口 |
| 本地排行榜被误认成真实排名 | 产品真实性风险 | 固定本地演示标识，禁用全网话术 |
| Remix 修改商业字段 | 合规和品牌风险 | schema 白名单、锁定字段、审计和负向测试 |
| 每日任务依赖设备时间 | 可被修改时间绕过 | 异常检测、审计和无奖励安全降级 |
| ImageGen 素材被误当授权素材 | 商业发布风险 | 资产清单标记来源与 `LOCAL_DEMO` |
| 多页面状态不一致 | 用户无法判断真实状态 | 统一 ID、单一 Repository、跨页面闭环测试 |

## 15. 决策 Gate

### Gate A：范围确认

确认五个模板、五个 Power 和前端本地边界。通过后进入 M0。

### Gate B：批次 A 设计确认

确认寻物、物理挑战、异步挑战和分享卡的结构、视觉方向和验收用例。通过后进入开发。

### Gate C：玩法闭环验收

批次 A 达到 85 分且无阻断问题后，才启动批次 B 的完整素材生产。

### Gate D：跨游戏接入验收

每个 Power 至少接入三个指定对象，且版本、事件和状态一致。

### Gate E：本地发布闭环验收

从自然语言描述到本机首页发布、体验、记录、Remix、暂停和回滚全部通过。

### Gate F：服务端接入评审

本期不执行。只有本地闭环达到 Definition of Done 后，才单独评审真实排行榜、账户同步、连接器和归因服务。
