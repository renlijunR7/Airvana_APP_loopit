# Airvana 未完成功能闭环审计

> 版本：v1.1
> 日期：2026-08-11
> 文档状态：待产品确认，确认前不继续扩展功能开发
> 当前边界：前端演示优先；本地服务、第三方服务和生产基础设施分别标注

## 1. 结论先行

当前项目已经形成较完整的移动端产品外观、页面入口和本地演示状态，但还不能等同于可公开运营的生产 APP。

26 个结构化模块中：

- **前端展示较完整**：启动、Playable 体验、发现、关系、创作器、AI 分身、增长网络、权益页面等。
- **本地服务已有、移动端未完全接线**：登录会话、Agent 任务、内容版本、审核、通知、Campaign、钱包、治理等。
- **必须接第三方**：真实 KYC、邮箱/Google 登录、社交渠道连接器、真实 AI 媒体生成、链上广播/托管。
- **必须建设生产基础设施**：PostgreSQL、分布式队列、对象存储/CDN、密钥管理、监控告警、备份恢复、容量与灰度发布。
- **本次 Android APK**：是可安装的前端演示包，不包含 Node.js/SQLite 后端，不代表上述真实服务已上线。

因此下一阶段不建议继续零散增加页面。应先收敛 5 条主链路：

1. 账号与角色资格链。
2. Agentic Playable 创作发布链。
3. Campaign 合作与归因结算链。
4. 玩家体验与社交留存链。
5. 治理、运维与数据生命周期链。

## 2. 统一闭环定义

一个模块只有同时具备以下环节，才标记为“闭环完成”：

`入口 → 权限/前置条件 → 核心操作 → 服务端权威状态 → 结果通知与审计 → 失败/重试 → 暂停/撤销/回滚 → 数据导出或删除`

统一状态标记：

| 标记 | 含义 |
| --- | --- |
| D | 仅前端/本地演示，不能作为真实业务结果 |
| L | 本地服务已有，但移动端或模块间尚未完整接线 |
| X | 依赖第三方服务、真实凭证或外部审核 |
| P | 依赖生产基础设施、运营组织或合规流程 |
| C | 推荐产品方案，仍待确认 |

## 3. 五条主链路及核心断点

### 3.1 账号与角色资格链（P0）

目标链路：

`启动 → 注册/登录 → 玩家账号 → 申请 KOL → KYC → 平台审核 → 商业权限 → 暂停/恢复/降级/注销`

未完成：

- 邮箱验证码、Google OAuth、设备与会话管理未形成生产闭环（L/X/P）。
- 创作者审核与 KYC 目前是两条独立演示状态；商业权限组合规则未最终确认（C）。
- 缺少补充材料、拒绝原因、重提、申诉、审核 SLA 和人工审核台（P）。
- 缺少 KYC 过期、角色暂停、连接器撤权、AI 分身暂停的联动（X/P）。
- 缺少逐 Playable 数据删除、全账号删除、合同/争议证据保留规则（P）。

推荐门槛：

`commercial_entitlement = 创作者审核通过 AND KYC 有效 AND 账号正常`

角色视角切换只能改变页面内容，不得提升真实权限。

### 3.2 Agentic Playable 创作发布链（P0）

目标链路：

`Campaign Brief → Campaign Contract → 能力编排 → Asset Manifest → 生成任务 → 预览/QA → 审核 → 发布 → 版本/暂停/回滚 → Remix`

未完成：

- 前端创作器与本地 Worker/AI Adapter 尚未形成统一任务状态机（L）。
- 图片、视频、音频、3D 等真实生成与失败恢复未接（X/P）。
- 素材上传仍缺对象存储、病毒/内容扫描、授权凭证、CDN 与生命周期（P/X）。
- Remix 仍需服务端保留来源、授权、父子版本、差异与撤销关系（L/P）。
- 审核、发布、暂停、回滚和 Kill Switch 尚未由统一服务端权限执行（L/P）。
- 生成完成不能直接等同发布成功；外部发布必须再次人工确认。

### 3.3 Campaign 合作、归因与结算链（P0）

目标链路：

`品牌机会 → KOL 申请/邀请 → Contract 版本与锁定 → 作品交付 → 有效事件 → 归因证据 → 对账 → 审核 → 支付/争议`

未完成：

- Contract 尚缺服务端版本、签署、锁定字段变更申请和审批记录（L/P/X）。
- 真实追踪链接、Click ID、事件幂等、去重、防刷、隐私同意和证据留存未完成（P）。
- AIP 站内权益与 KOL 商业结算虽有界面/本地账本，但生产账本、托管/支付、税务、退款和争议规则未完成（L/X/P）。
- Telegram、Facebook、X、Discord 连接器缺 OAuth/Bot、Token Vault、目标选择、回调、重试与撤销（X/P）。
- 玩家作品不得自动商业化；需要“复制为 KOL 商业版本”并重新走 Contract 与审核（C）。

### 3.4 玩家体验与社交留存链（P1）

目标链路：

`发现 → 体验 → 互动/收藏/分享 → 关注关系 → 消息 → 重访 → 举报/屏蔽`

未完成：

- Playable 当前主要由前端静态资产承载，缺统一 Artifact 托管、超时、刷新、失败和运行证据（P）。
- 推荐、搜索、关注、获赞、收藏、消息的跨页面权威数据未统一（L/P）。
- 通知/私信缺实时推送、未读同步、发送失败重试、屏蔽和风控（L/P/X）。
- 搜索缺统一索引、建议、历史、筛选、错误与无结果推荐（P）。
- 分享需区分“调用系统分享”“复制成功”“渠道发布成功”，不能用前端动作冒充外部结果。

### 3.5 治理、运维与数据生命周期链（P0）

目标链路：

`举报/自动风险 → 受理 → 暂停/下架 → 证据 → 人工裁决 → 申诉 → 恢复/维持 → 审计`

未完成：

- 风险策略、审核角色、处置 SLA、事故分级、告警和最终裁决未生产化（P）。
- 账号封禁、KOL 暂停、单作品下架、渠道暂停、结算冻结应拆成不同控制，不应共用一个开关（C/P）。
- 缺统一日志、指标、追踪、崩溃报告、监控告警、灰度、回滚和容量测试（P）。
- 缺数据库备份/恢复演练、对象存储保留策略、密钥轮换和连接器 Token 撤销（P）。
- 未成年人模式缺年龄段、监护同意、内容/社交/钱包限制和地区规则（X/P）。

## 5. 横向技术底座

### 5.1 已经具备的本地服务能力

当前项目不是纯静态页面。`/workspace` 已连接 Node.js + SQLite，本地 MVP 已具备部分真实状态机：

- 钱包签名登录、会话、钱包绑定、导出和删除申请。
- Agent 创建、任务执行、人工审核、取消、重试和 Kill Switch。
- 内容生成、发布、计划发布、归档、版本恢复和 HTML Artifact。
- Campaign 创建、平台审核、KOL 申请/邀请、交付与重交。
- Runtime session/events、engagement 和 attribution touch。
- AIP ledger、AIT withdrawal 预留、审批和 tx hash 门槛。
- 举报、申诉、风险案件和通知。

这些能力仍属于**单节点本地服务闭环**，尚未等同于生产部署。移动端 `/` 默认使用前端演示数据，第一优先事项是通过统一 Data Adapter 接入上述权威状态，避免两套业务状态长期漂移。

### 5.2 仍属于纯前端演示的核心能力

- 玩家/KOL 视角与商业 entitlement。
- 移动端能力编排、模板和 Asset Manifest。
- 完整社交关系、私信与推送。
- KYC 结果。
- 外部连接器真实发布。
- AI 分身训练、实时生成和渠道代理。
- 增长网络、节点、信用分和经济权限。
- 移动端商业归因、链上结果与结算。

### 5.3 需要建设的底座

建议先完成以下底座，再按页面扩展：

| 编号 | 底座 | 完成标准 |
| --- | --- | --- |
| B01 | 统一数据适配层 | 页面只调用统一接口，可切换 mock/local/staging，不再各自判断演示模式 |
| B02 | 权限与角色服务 | 玩家、KOL、KYC、Contract、渠道、结算均由服务端 entitlement 判定 |
| B03 | 统一任务状态机 | AI 生成、审核、发布、连接器均具备 pending/running/success/failed/cancelled |
| B04 | 对象与版本模型 | account、playable、version、asset、contract、event、settlement 有稳定 ID 和关系 |
| B05 | 全局状态组件 | Loading/Empty/Error/Offline/Permission/Review/Expired 全项目统一 |

| B07 | 移动交付 | 正式包名/签名、API 认证、深链、权限、安全区、离线与商店合规 |
| B08 | 自动化质量门禁 | 单元/合同/行为/E2E/视觉/性能/安全测试进入 CI |

## 6. 推荐实施顺序

### 第一批：建立可相信的产品状态（P0）

1. B01 数据适配层 + B02 权限服务。
2. 玩家→KOL 申请、KYC、审核、暂停和降级状态机。
3. Brief→Contract→创作任务→审核→站内发布主链。
4. Asset Manifest 真实上传与授权证据。
5. 事件/归因证据与治理审计基础。

### 第二批：完成商业与外部闭环（P1）

1. 品牌组织、合作申请、Contract 变更与签署。
2. 连接器 OAuth、人工确认、回调、重试和撤销。
3. AIP 权益与 KOL 商业结算分账。
4. AI 分身真实媒体服务、授权、版本与渠道。
5. 消息、搜索、关系和跨页面数据一致。

### 第三批：增长与规模化（P2）

1. 五人节点、Power、信用分和贡献证据。
2. 多人/实时互动与更完整的社区能力。
3. 全量国际化、无障碍与未成年人保护。
4. A/B 测试、自动优化建议与容量扩展。

## 7. 需要产品确认的 10 个决策

1. 是否确认商业权限公式：创作者通过 + KYC 有效 + 账号正常。
2. 玩家作品转商业作品是否采用“复制为 KOL 版本”，禁止原地自动升级。
3. 第一版真实后端范围：仅账号/作品/审核，还是同时纳入 Campaign/归因/结算。
4. 第一版 AI 分身是否接真实视频/声音，还是继续前端演示。
5. 第一版外部渠道是否只接 1 个试点渠道，再扩到 4 个。
6. AIP 是否始终为不可提现站内权益；KOL 商业结算是否使用独立账本。
7. 五人网络第一版是否仅做协作关系，暂不做经济节点和智能合约。
8. KOL 审核 SLA、拒绝重提、申诉、暂停与主动降级规则。
9. 第一版目标是内部演示 APK、封闭内测，还是应用商店生产版。
10. 第一版支持语言、地区、未成年人和 KYC 范围。

## 8. 验收原则

- 任何真实权限必须由服务端确认，视角切换和本地状态不能升级权限。
- Agent 只能修改 Contract 允许字段，不能改变预算、结算、合规、渠道授权和 Kill Switch。
- 未经人工批准不得发布、外发、支付、结算或执行高风险 Web3 动作。
- 外部服务不可用时必须失败关闭，并提供重试、撤销或人工接管。
- 演示、待接入、审核中和真实成功必须使用不同状态和文案。
- 每个 P0 链路必须具备自动化测试、审计证据和回滚方案。
